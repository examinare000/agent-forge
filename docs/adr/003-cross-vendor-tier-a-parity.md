# ADR-003: クロスベンダー最上位ティアモデルを Tier A 同格の判断役として扱う

- ステータス: 採用済み
- 日付: 2026-07-25
- 最終更新日: 2026-07-25

## 背景

クロスベンダーの最上位ティアモデル（Codex 等）はフラッグシップ（Tier A）同等以上の推論性能を持つに至ったが、本フレームワークの規範は「コードのオフロード先」としてしか位置づけておらず、設計判断・敵対的検証級の役割を与えていなかった。配布物のためモデル名の陳腐化も避ける必要がある。

## 検討した選択肢

1. **名指しゲート（adversarial-verifier PASS）の代替として自由に使えるようにする** — 常時ロード文脈に無限定の許可文が載ると、完了ゲートが恣意的にバイパスされうる。adversarial-verifier の read-only 性が担保する検証の独立性も引き継がれない。棄却（詳細: [docs/trial-log/cross-vendor-tier-a-parity.md](../trial-log/cross-vendor-tier-a-parity.md)）。
2. **能力ベース表現で同格の判断役としつつ、ゲート体系は維持する** — 設計第2案・クロスベンダー第3票は通常運用から解禁。敵対的検証の代替検証役は「検証役を自ベンダー Tier A で維持できない場合」に限定し、発動の1行宣言 + read-only 起動（タスク文で propose-only 明示）を義務化。採用。

## 決定

選択肢 2 を採用。rules/02（正本）・rules/03（起動規律）・rules/hosts/claude/02（降格手順の中間段）・claude/CLAUDE.core.md（常時ロード側の限定付き許可）・skills/dual-track-proposals（同格の提案者・内容評価）に一貫して明記。モデル名はハードコードせず「クロスベンダー最上位ティア」「Tier A/B」の能力・ティア表現のみを用いる。

## 理由

判断力の実態に規範を追従させつつ、品質担保の核である「メインより強い検証者」の非対称構造と名指しゲートを崩さないため。検証役の Tier A ピン維持の手段としてクロスベンダーを位置づけることで、自ベンダー下位ティアへの降格を最終手段に後退させ、劣化時の検証品質をむしろ引き上げる。

## 結果

- dual-track proposals で Codex 案が主案採用されることが正規の結果として明文化された（出自ではなく内容で評価）。
- 検証役の降格ラダーが「自ベンダー Tier A → クロスベンダー最上位（read-only）→ 自ベンダー下位ティア」の三段になった。
- 制約はプロンプト規律であり機構的強制ではない（他ベンダー CLI にツール制限を課せないため）。運用上の残余リスクとして受容。
