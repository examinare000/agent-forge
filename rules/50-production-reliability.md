# 50. プロダクション信頼性
本番環境での障害を防ぐ防御的設計とインターフェース契約。テスト戦略は採用者が追加する規約に従う（`00-core-principles.md`「工学規約は採用者が追加する」参照）。

## 原則
- **防御的設計**: 外部入力（API・設定・環境変数）はすべて疑い、デフォルト値で安全にフォールバックする。
- **契約検証**: API/データ構造を明示的に検証し、構造不正時は早期に例外を投げる。ユーザー向けには汎用エラー、ログには詳細。
- **外部境界の失敗モードは例外だけではない**（実測: ハングしたまま exit 0 が 3 夜連続の偽成功を生んだ）:
  1. 外部 I/O の待機には必ず上限時間を置き、タイムアウトを**既存のエラー型へ正規化して**既存のリカバリ経路へ合流させる。
  2. 子プロセスはプロセスグループ全体へ TERM、猶予後 KILL を送る（親だけの kill では停止しない）。
  3. **無人・自動実行経路の成功判定は終了コードだけで行わず、成果物の実体**（checksum・receipt・対象ファイルの実在）で照合する。
  4. 「ブロックし得る」と一箇所でも認めた失敗クラスは、同じ境界の全操作へ横展開する。

## 品質チェック
- **テスト**: プロジェクトに存在するテストスイートを通す（無いスイートを要求しない）。

---
**適用優先度**: 🔴 最高（プロダクションコード必須）
