# 00-core-principles.md

## 絶対遵守の3原則
1. **デグレ防止**: 既存機能を破壊しない。既存テストを壊した変更はロールバックしてよい（fix-forward が適切ならそれでよい）。
2. **日本語統一**: 返答、コメント、エラー、テスト、コミット、ドキュメントは全て日本語。思考・検索のみ英語可（コードの命名は英語慣習に従う）。本フレームワークの既定であり、プロジェクト側 CLAUDE.md/AGENTS.md で言語指定があればそちらを優先する。
3. **検証をもって完了とする**: 完了・成功の主張には、実行した検証コマンドと結果を必ず添える。未検証の楽観的主張（「これで動くはず」等）は禁止。

## 工学規約は採用者が追加する
本フレームワークはコアに個人の工学的嗜好（git 戦略・テスト戦略・言語/環境固有の規約など）を持たない。
採用者は自分の規約を `10-29`（ワークフロー）/ `70-89`（言語・環境）番帯に自分のルールとして追加する（レイヤ表は `README.md` 参照）。

## 開発サイクル（非自明な変更ではこの順序を既定とする）
1. ブランチ作成（git 規約は採用者が 10〜29 番帯に追加する）
2. 設計判断を伴う時は ADR・設計更新（`30-documentation-management.md`）
3. 実装（テスト戦略は採用者が 10〜29 番帯に追加する）
4. アトミックコミット（シークレット混入なし・デバッグコード削除済みを確認してから）
5. 品質チェック（test / lint / typecheck）➔ マージ

## 優先度・適用範囲
- **適用**: 全言語、全フェーズ、全プロジェクト。
- **優先度**: 🔴 絶対最高（本ファイルは憲法であり常に最上位。それ以外のルールは番号が大きいファイルを優先する。改訂はユーザー承認と PR 経由）。
