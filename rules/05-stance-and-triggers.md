# 05. 判断の構えとハードトリガ（発火条件の正本）

**本ファイルは provider 中立であり、メインセッションを誰が担うかに依らず全員へ適用される。**

## 判断の構え

開始時に判定するのは分岐表ではなく構えである。タスクの性質を `04-principles.md`（思考原則・金言集）に照らし、
必要な構え（深さ・計画・分割・委譲）を自分で選ぶ。**構えは排他ではなく重ねる**。

- 前提が崩れると高くつく非自明タスクには深い推論 ➔ `93-deep-reasoning-protocol.md`
- 専門判断・文脈隔離・独立レビューが効く形にはサブエージェント品質ゲート ➔ `91-subagent-quality-gate.md`

## ハードトリガ

環境事実と義務であり、構え判断に委任しない。**該当したら発火する**。

| トリガ | 発火先 | 備考 |
|---|---|---|
| 非自明な計画立案に入った（ツール呼び出し 1〜2 回で足りる調査・数行の変更計画は対象外） | `92-plan-mode-protocol.md` | 発火点は下記「機構非対応時の縮退」を参照 |
| 教訓トリガー該当（バグ根本原因確定・レビュー指摘サイクル完了・ユーザー訂正） | `94-self-improvement-protocol.md` | キャプチャ義務。振り返り手続きは provider 固有（下記） |
| 試行の打ち切り・棄却・委譲先の選び直し | `94-self-improvement-protocol.md`（trial-log） | 失敗・棄却は必須発火 |
| 判断停滞（次のいずれか 1 つ）: 同種の指摘が 2 回続く／指摘数が 1 回で半減しない／修正が別の誤りを生む／合格基準・完了条件が未決定／自分の判断で範囲・規則を広げ始めた／既決事項を覆す必要が出た | `03-agent-behavior.md`「判断停滞のエスカレーション」 | 往復を続けず即時発火。上げる経路と報告の形は 03 が正本 |
| ユーザーの明示指示（「深く考えて」「委譲して」等） | 該当プロトコルを即時発火 | — |

## 機構非対応時の縮退（provider 差の吸収）

発火**条件**は全 provider 共通であり、機構の有無で免除されない。機構を持たない provider は以下で代替する。
各 provider の適用状況の一覧は README の適用マトリクス。**他ファイルは縮退を再説明せず本節を参照する。**

| 機構 | 保有 provider での発火 | 非保有 provider での縮退 |
|---|---|---|
| plan mode | 非自明な計画で plan mode に入った時に 92 を発火 | 「計画して」「プランを立てて」等の**計画依頼を受けた時点**で（非自明なら）92 を発火する |
| Skill | 手続き本体を Skill としてロード（`deep-reasoning` / `plan-deep-research` / `trial-log` 等。`retrospect` は別頒布の recall リポジトリ導入環境のみ・optional） | 対応する `~/.claude/skills/<name>/SKILL.md` を**直接読んで**同じ手順に従う |
| native subagent | 論理ロールをサブエージェントへ委譲 | 委譲を要する義務（独立レビュー・第3票）をクロスベンダー MCP 相互検証またはユーザー承認で代替する（実行不能な義務は課さない。`02-model-fallback-matrix.md`「義務の代替」） |
| フック（PreToolUse 等） | フックが規約を実行前に強制 | 同じ規約を**規律として**遵守する（例: 変更系 git/gh は `git-compose` ロールへ委譲） |
| 教訓の昇格インフラ（corpus / 意味検索 / 定期実行） | `94` のキャプチャ〜昇格まで実行 | 教訓候補と試行の記録を完了報告に記載するまでを義務とし、昇格はインフラ保有セッションへ引き継ぐ（引き継ぎ先が無ければユーザーへ提示する） |

---
**適用優先度**: 🔴 絶対（全 provider・全セッション。発火条件の正本）
